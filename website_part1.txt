STEP 2: Train / Test Split
---------------------------
Phase: Data Collection
Heading: "We Split the Data Into Two Separate Sets"

Explanation:
To prevent cheating, the model NEVER sees test data during training.
We split the dataset chronologically (NOT randomly — this is important
for time-series data).

Visual — a horizontal timeline bar:

  |<------------ TRAIN DATA (240,000 candles) ----------->|<--- TEST DATA (35,903 candles) --->|
  Jan 2021                                         ~Oct 2024                               Feb 2025

Two stat cards:
  Training Set: 240,000 candles | ~83% of data | Used to TEACH the models
  Test Set:      35,903 candles | ~17% of data | Used to EVALUATE (never seen by model)

Important note (highlight box):
"Why not random split? Because financial data is time-ordered.
If we randomly split, future data leaks into training — the model
would be 'cheating' by learning from the future. We always split
by time: train on the past, test on the future."

STEP 3: Why Not Use Raw Prices?
---------------------------------
Phase: Feature Engineering
Heading: "Raw Prices Are Meaningless Across Time"

Explanation:
A model trained on raw prices like $16,500 from 2021 cannot generalize
to $65,000 prices in 2024. We need RELATIVE features — values that
describe the SHAPE and MOVEMENT of each candle, not the absolute price.

Visual — two side-by-side columns:

  RAW PRICE (bad for ML)          | RELATIVE FEATURE (good for ML)
  --------------------------------|-------------------------------
  Open = $16,541                  | Body = (Close - Open) / Open = +0.0049
  Close = $16,630                 | Upper Wick = (High - Close) / Close = +0.0011
  High = $16,648                  | Lower Wick = (Low - Open) / Open = -0.0008
  >> changes every year           | >> always same scale, always comparable

"The relative feature answers: 'Was this a strong up candle or a weak one?'
regardless of whether BTC was $5,000 or $65,000 at the time."

---

STEP 4: The 8 Price-Action Features
--------------------------------------
Phase: Feature Engineering
Heading: "We Engineered 8 Features From Each Candle"

Explanation:
For each 15-minute candle, we compute 8 values that describe its behavior:

Show as a clean numbered list with formula + plain English:

  Feature 1: Candle Body (direction + strength)
    Formula:  (Close - Open) / Open
    Meaning:  Positive = price went up. Negative = price went down.
    Example:  (16,549 - 16,541) / 16,541 = +0.000484 (small up candle)

  Feature 2: Upper Wick Height
    Formula:  (High - Open) / Open
    Meaning:  How far price spiked UP from the opening price
    Example:  (16,557 - 16,541) / 16,541 = +0.000968

  Feature 3: Upper Wick to Close
    Formula:  (High - Close) / Close
    Meaning:  Rejection at the top — how much price fell back from the high
    Example:  (16,557 - 16,549) / 16,549 = +0.000484

  Feature 4: Lower Wick Height
    Formula:  (Low - Open) / Open
    Meaning:  How far price dropped below the opening price
    Example:  (16,528 - 16,541) / 16,541 = -0.000786

  Feature 5: Lower Wick to Close
    Formula:  (Low - Close) / Close
    Meaning:  Rejection at the bottom — bounce strength
    Example:  (16,528 - 16,549) / 16,549 = -0.001269

  Feature 6: Full Candle Range (Open basis)
    Formula:  (High - Low) / Open
    Meaning:  Total volatility of the candle relative to open
    Example:  (16,557 - 16,528) / 16,541 = +0.001754

  Feature 7: Full Candle Range (Close basis)
    Formula:  (High - Low) / Close
    Meaning:  Total volatility relative to close
    Example:  (16,557 - 16,528) / 16,549 = +0.001753

  Feature 8: Volume
    Formula:  Raw trading volume (then scaled)
    Meaning:  How much BTC changed hands — high volume = conviction
    Example:  342.81 BTC → after scaling: 0.7231

Visual: show a single candle diagram (candlestick) with arrows pointing
to each feature location on the candle body and wicks.

STEP 5: Feature Scaling (MinMax Normalization)
------------------------------------------------
Phase: Feature Engineering
Heading: "Scaling Keeps All Features on Equal Footing"

Explanation:
Features 1-7 are tiny ratios (like 0.0005). Feature 8 (volume) is
a large number (like 342.81). Without scaling, volume would dominate
the model and the other 7 features would be ignored.

We use MinMaxScaler — fitted ONLY on training data, then applied to test:

  Before Scaling:                 After Scaling (0 to 1 range):
  Feature 1:  +0.000484           Feature 1:  0.5621
  Feature 2:  +0.000968           Feature 2:  0.6032
  Feature 3:  +0.000484           Feature 3:  0.5784
  Feature 4:  -0.000786           Feature 4:  0.4103
  Feature 5:  -0.001269           Feature 5:  0.3871
  Feature 6:  +0.001754           Feature 6:  0.6219
  Feature 7:  +0.001753           Feature 7:  0.6218
  Feature 8:  342.81              Feature 8:  0.7231

Important rule (highlight box):
"The scaler is FITTED on training data only, then APPLIED to test data.
If we fit the scaler on test data too, the model would have peeked at
the future — this is called data leakage."

STEP 6: Creating Sequences (Sliding Window)
--------------------------------------------
Phase: Preprocessing & Sequences
Heading: "The Model Looks Back 96 Candles to Predict the Next One"

Explanation:
The model does not predict from a single candle. It looks at the
last 96 candles (= 24 hours of 15-min data) and asks:
"Based on the past 24 hours, will the next candle go UP or DOWN?"

Visual — sliding window diagram:

  Candles:    [1][2][3]...[94][95][96] → [97]  = SAMPLE 1
                  [2][3][4]...[95][96][97] → [98]  = SAMPLE 2
                      [3][4][5]...[96][97][98] → [99]  = SAMPLE 3
                                               ↑
                                         TARGET (predict this)

Each sample X has shape: (96 candles × 8 features) = 768 numbers
Each target Y has shape: (8 features of the next candle)

Final dataset shape (show as stat cards):
  X_train shape: (239,904 samples, 96 timesteps, 8 features)
  Y_train shape: (239,904 samples, 8 features)
  X_test shape:  (35,807 samples, 96 timesteps, 8 features)
  Y_test shape:  (35,807 samples, 8 features)

Context:
"We predict all 8 features of the next candle, but we only USE Feature 1
(Candle Body = direction) to decide Long or Short. If predicted Feature 1 > 0,
the model thinks the next candle will be green (go long). If < 0, go short."

---

STEP 7: The Prediction Task
-----------------------------
Phase: Preprocessing & Sequences
Heading: "What Exactly Are We Predicting?"

Explanation:
The model is a REGRESSION model — it predicts actual values, not just
"up" or "down." But we convert its output to a binary trading decision.

Visual — flow diagram:

  Input:   Last 96 candles of 8 features each
      ↓
  Model:   Predicts all 8 features of the NEXT candle
      ↓
  Output:  Y_pred = [+0.0012, +0.0008, +0.0003, -0.0002, ...]
                         ↑
                   Feature 1 = Candle Body
      ↓
  Decision Logic:
    IF Feature 1 > 0  →  BUY (predict next candle is green)
    IF Feature 1 < 0  →  SELL (predict next candle is red)

Why regression instead of classification?
"A regression loss (MSE) forces the model to learn the MAGNITUDE of moves,
not just the direction. This gives richer gradients during training and
helps the model understand market structure better."

STEP 8A: Model Type 1 — Pure CNN (Convolutional Neural Network)
-----------------------------------------------------------------
Phase: Model Architecture
Heading: "CNN: A Pattern Scanner That Slides Across Time"

Explanation:
A CNN uses a small "window" (kernel) that slides across the 96-candle
sequence one step at a time, scanning for local patterns — like a
magnifying glass moving across a price chart.

Visual — kernel sliding animation:

  INPUT: 96 candles × 8 features
  (imagine a grid: 96 columns, 8 rows — each cell is one scaled number)

  KERNEL (size 3): scans 3 consecutive candles at a time

  Step 1:  [candle 1, candle 2, candle 3]  → outputs 1 number ("pattern score")
  Step 2:  [candle 2, candle 3, candle 4]  → outputs 1 number
  Step 3:  [candle 3, candle 4, candle 5]  → outputs 1 number
  ...      slides all the way to candle 96

  Each kernel produces 96 scores (one per position, padding=1 keeps length same)

LAYER 1 — Conv1D with 32 filters:
  32 different kernels slide across the sequence simultaneously.
  Each kernel is looking for a DIFFERENT pattern.
  Kernel 1 might detect: "two red candles then a big green" — a reversal.
  Kernel 2 might detect: "three rising candles with increasing volume" — momentum.
  Kernel 3 might detect: "flat then sudden spike" — breakout.
  Output: 96 positions × 32 filter responses = a richer representation.

Activation — GELU:
  After Conv1D layer, every output passes through GELU activation.
  GELU = "keep strong signals, soften weak ones, kill negative ones."
  It is smoother than ReLU — handles financial data's noisy values better.
  Visual: show a curve — below 0 is dampened, above 0 grows naturally.

LAYER 2 — Conv1D with 64 filters:
  A second kernel scan on the already-processed output of Layer 1.
  Now 64 kernels look for HIGHER-LEVEL patterns:
  "A pattern-of-patterns" — e.g., a momentum burst followed by consolidation.
  Output: 96 positions × 64 features (deeper, richer understanding).
  Another GELU activation.

Taking the last position:
  After both Conv layers, we have 96 × 64 values.
  We take ONLY the last position (candle 96's representation).
  This is the model's summary of everything it saw — "based on the full
  24-hour history, here is my understanding of right NOW."

OUTPUT LAYER — Linear(64 → 8):
  A single fully-connected layer maps the 64 summary values
  down to 8 output values — the predicted features of the next candle.
  Feature 1 of output > 0 → predict next candle is green (go Long).

Full flow summary:
  Input (96×8) → Conv1D-32 → GELU → Conv1D-64 → GELU
                → take last step (64 values) → Linear → Output (8 values)

Accuracy of CNN models:
  CNN-A1: 50.96%  |  CNN-A2: 50.55%
  "CNN sees local patterns well but has no long-term memory."

STEP 8B: Model Type 2 — Pure LSTM (Long Short-Term Memory)
------------------------------------------------------------
Phase: Model Architecture
Heading: "LSTM: A Memory Cell That Reads the Sequence Like a Story"

Explanation:
LSTM is a type of recurrent neural network. Instead of scanning with
a sliding window, it reads the sequence one candle at a time, updating
an internal "memory" as it goes — like a trader who reads each candle
in order and keeps notes about what matters.

Visual — LSTM unrolled over time:

  Memory state (h) starts at zero.

  Candle 1 → LSTM cell → updates memory → passes to next
  Candle 2 → LSTM cell → updates memory → passes to next
  Candle 3 → LSTM cell → updates memory → passes to next
  ...       (repeats 96 times)
  Candle 96 → LSTM cell → FINAL memory state (h_96)
                              ↓
                        This captures the full 24-hour context

Inside the LSTM cell — 4 gates (explain simply, no formulas):
  FORGET gate:  "Should I erase something from memory?"
                e.g., if BTC was in a downtrend but it just reversed,
                forget the old downtrend memory.

  INPUT gate:   "Should I store this new candle's information?"
                e.g., a sudden high-volume candle — yes, remember this.

  OUTPUT gate:  "What part of memory is relevant RIGHT NOW?"
                e.g., if we are near a resistance level, activate that memory.

  CELL state:   The "long-term memory highway" — carries important context
                all the way from candle 1 to candle 96 without forgetting.

Hidden size = 64:
  The LSTM has 64 "memory slots" — 64 different things it can remember
  simultaneously about the price history.
  These 64 slots learn WHAT to remember during training.

OUTPUT LAYER — Linear(64 → 8):
  After reading all 96 candles, the final hidden state (64 numbers)
  is passed through a linear layer → 8 output predictions.

Full flow summary:
  Input (96×8) → LSTM(hidden=64, reading candle-by-candle)
               → take final hidden state h_96 (64 values)
               → Linear(64→8) → Output (8 values)

Accuracy of LSTM model:
  LSTM-B1: 52.07%
  "LSTM has the highest individual accuracy — its long-term memory
   gives it an edge for detecting multi-hour BTC patterns."

STEP 8C: Model Type 3 — CNN + LSTM Hybrid
------------------------------------------
Phase: Model Architecture
Heading: "Hybrid: First Scan for Patterns, Then Remember Them Over Time"

Explanation:
The Hybrid model is a two-stage architecture. It first uses CNN to detect
local patterns in each window, then passes those pattern summaries into
an LSTM that remembers how those patterns evolve over the full 24 hours.

Visual — two-stage pipeline:

  STAGE 1: CNN layer extracts local patterns
  ──────────────────────────────────────────
  Input: (96 candles × 8 features)
  Conv1D with 64 filters, kernel size 3:
    Slides across sequence → at each position, detects short-term patterns
    Output: (96 positions × 64 pattern scores)
  GELU activation: keeps strong pattern responses, dampens noise.

  "The CNN has converted raw price data into pattern descriptions.
   Instead of [open, high, low, close, volume...], each position
   now holds [pattern-1-score, pattern-2-score, ..., pattern-64-score]"

  STAGE 2: LSTM reads the pattern sequence over time
  ───────────────────────────────────────────────────
  Input: the (96 × 64) output from CNN stage
  LSTM with hidden size 32:
    Now reads pattern scores one step at a time.
    Instead of remembering raw candles, it remembers HOW PATTERNS EVOLVE.
    e.g., "the breakout pattern at candle 20 was followed by the
    momentum pattern at candle 35 — that combination usually leads to..."
  Takes the final hidden state h_96: 32 values.

  OUTPUT LAYER — Linear(32 → 8):
    Maps 32 hybrid-context values → 8 output predictions.

Full flow summary:
  Input (96×8) → Conv1D-64 → GELU
               → reshape to (96×64 pattern sequence)
               → LSTM(hidden=32, reads pattern-by-pattern)
               → take final h_96 (32 values)
               → Linear(32→8) → Output (8 values)

Why this is powerful:
  CNN sees WHAT patterns exist locally.
  LSTM sees HOW those patterns evolve over time.
  Together: "I see a consolidation pattern developing over the last
  8 hours, and historically when this happens after a big move, price
  tends to break upward."

Accuracy of Hybrid models:
  Hybrid-C1: 51.21%  |  Hybrid-C2: 51.76%

STEP 10: Training Process
---------------------------
Phase: Training & Ensemble
Heading: "How Were the Models Trained?"

Explanation:
Training = showing the model thousands of examples so it learns

Visual — training loop diagram:

  For each batch of training samples:
    1. Feed 96 candles into model → get predicted next candle features
    2. Compare prediction vs actual (MSE Loss)
    3. Calculate how wrong we were (error)
    4. Backpropagate: adjust weights to reduce error
    5. Repeat for next batch

Key settings:
  Loss Function:    MSE (Mean Squared Error)
  Optimizer:        Adam
  Sequence Length:  96 candles (= 24 hours)
  Device:           CUDA GPU (Google Colab)
  Batch Processing: Chunked into 16 parts (memory management)

"The model was saved at multiple checkpoints during training.
We kept the checkpoint that produced the highest backtest equity —
not necessarily the lowest training loss."

STEP 11: Ensemble Voting — Combining 5 Models
-----------------------------------------------
Phase: Training & Ensemble
Heading: "5 Models Vote on Every Trade — Like a Committee"

Explanation:
Instead of trusting one model's opinion, we ask all 5 models.
Each model outputs: Feature 1 > 0 (Long vote) or < 0 (Short vote).
Then we use WEIGHTED voting — better models get louder votes.

Visual — voting example:

  Model A1 (CNN)    → Feature 1 = +0.0012 → Vote: LONG  | Weight: 5/15
  Model A2 (CNN)    → Feature 1 = +0.0008 → Vote: LONG  | Weight: 4/15
  Model B1 (LSTM)   → Feature 1 = -0.0003 → Vote: SHORT | Weight: 3/15
  Model C1 (Hybrid) → Feature 1 = +0.0005 → Vote: LONG  | Weight: 2/15
  Model C2 (Hybrid) → Feature 1 = +0.0002 → Vote: LONG  | Weight: 1/15

  Weighted Long Score  = 5/15 + 4/15 + 2/15 + 1/15 = 12/15 = 0.80
  Weighted Short Score = 3/15 = 0.20

  Agreement = 80% (4 out of 5 models agree → LONG)
  Final Decision: GO LONG ✓

"Graduated weights [1,2,3,4,5] give more influence to later models
which are often better trained. This is smarter than equal 1-vote-each."

STEP 12: Consensus Gate — Filtering Low-Confidence Trades
-----------------------------------------------------------
Phase: Training & Ensemble
Heading: "We Only Trade When 80%+ of Models Agree"

Explanation:
After weighted voting, we have a direction (Long or Short) and an
agreement percentage. The question is: at what threshold do we trade?

Two thresholds compared — show as side-by-side comparison:

  WITHOUT Consensus Gate (Baseline — all versions up to v7):
  ──────────────────────────────────────────────────────────
  Threshold: >50% agreement (simple majority vote)
  In practice with 5 models: ANY result where 3 or more agree.
  3/5 = 60%  → TRADE  ✓
  4/5 = 80%  → TRADE  ✓
  5/5 = 100% → TRADE  ✓
  Effectively: every single candle is traded (35,903 trades).
  Win rate: ~50% (essentially random — barely better than a coin flip)
  "The model is trading even on its least confident, most uncertain signals."

  WITH Consensus Gate (v8 onwards — our improvement):
  ────────────────────────────────────────────────────
  Threshold: ≥80% agreement (4 or 5 of 5 models must agree)
  3/5 = 60%  → SKIP  ✗  (too uncertain)
  4/5 = 80%  → TRADE ✓
  5/5 = 100% → TRADE ✓
  Trades taken: 24,900 out of 35,903 (69.4%)
  Win rate: 52.04% — a genuine +2% improvement.
  "We removed 30.6% of trades — the uncertain ones. What remained
   was cleaner, more reliable signals from the ensemble."

Visual — trade/skip decision table:

  Agreement | Without Gate | With Gate (≥80%) | Win Rate (with gate)
  ----------|--------------|-------------------|---------------------
  60%       | TRADE ✓      | SKIP ✗           | N/A (filtered out)
  80%       | TRADE ✓      | TRADE ✓          | ~52%
  100%      | TRADE ✓      | TRADE ✓          | ~52.4%

Result stats (from actual v9 backtest):
  Total test candles     : 35,903
  Trades taken (≥80%)    : 24,900  (69.4% of candles)
  Filtered out (<80%)    : 11,003  (30.6% — too uncertain)
  ML Accuracy before gate: 51.91%  (on ALL 35,903 candles)
  Trading Win Rate after : 52.04%  (on 24,900 taken trades only)
  Gate improvement       : +0.15% accuracy gain
  Precision after gate   : 0.5185   Recall: 0.7657   F1: 0.6183

"The consensus gate is not magic — it removed 30.6% of the noisiest
candles and kept the 69.4% where models had higher agreement.
The win rate improvement (+0.15%) is small but real and consistent
across all test versions that used this filter (v8, v9, v10, v11...)"

STEP 13: What Is Backtesting?
-------------------------------
Phase: Backtest Decision Logic
Heading: "Backtesting = Simulating Live Trading on Past Data"

Explanation:
We cannot test in real markets yet. Instead, we replay the test set
(35,807 candles = ~374 days) and simulate what would have happened
if we had traded with our system.

Visual — backtest simulation flow:

  For each 15-minute candle in test set:
    1. Feed last 96 candles to all 5 models
    2. Get weighted vote → Long or Short
    3. Check consensus ≥ 80%? If not → skip
    4. Calculate position size (based on equity tier + modifiers)
    5. Execute: if Long and candle closes up → profit | closes down → loss
    6. Record equity
    7. Move to next candle

Starting capital: $1,000
Duration: 374 days (~35,807 candles)
Final equity (v9): $4,822

---

STEP 14: Equity Milestone Tier Sizing
----------------------------------------
Phase: Backtest Decision Logic
Heading: "Position Size Grows With Your Account — But Safely"

Explanation:
Instead of risking a fixed % (which compounds losses) or a fixed $
(which doesn't scale with wins), we use MILESTONE TIERS:

Visual — tier table:

  Account Equity       | Position Size Per Trade
  ---------------------|------------------------
  < $1,500             | $750   (conservative — protect the base)
  $1,500 — $3,000      | $1,000 (growing — moderate risk)
  $3,000 — $5,000      | $1,300 (established — reward the growth)
  > $5,000             | $1,600 (high confidence — maximize gains)

"The tier only steps UP when equity crosses a threshold, and stays
at the lower tier if equity falls back. This compounds WINS without
compounding LOSSES — the key insight from v6."

Example scenario:
  Start: $1,000 → use $750 per trade
  After growth: $2,000 → upgrade to $1,000 per trade
  Bad run: equity drops to $1,800 → stays at $1,000 (does NOT drop back)
  Recovers to $3,200 → upgrades to $1,300 per trade

STEP 15: Dynamic Velocity Scoring (v9's Unique Innovation)
------------------------------------------------------------
Phase: Backtest Decision Logic
Heading: "Bet More When Hot, Bet Less When Cold"

Explanation:
Every trade, we track the win rate of the LAST 50 trades (rolling window).
If recent win rate is above 50%, the system is "hot" → bet bigger.
If below 50%, the system is "cold" → bet smaller. Automatically.

Formula:
  velocity_multiplier = 1.0 + (recent_win_rate - 0.50) × 4.0
  Capped between 0.30x (minimum) and 2.00x (maximum)

Visual — multiplier table:

  Recent Win Rate | Velocity Multiplier | Meaning
  ----------------|---------------------|-------------------------
  70%             | 1.0 + (0.20×4) = 1.80x | Hot streak → bet 80% more
  60%             | 1.0 + (0.10×4) = 1.40x | Good run → bet 40% more
  50%             | 1.0 + (0.00×4) = 1.00x | Neutral → base size
  40%             | 1.0 + (-0.10×4)= 0.60x | Cold → bet 40% less
  30%             | 1.0 + (-0.20×4)= 0.20x → capped to 0.30x | Very cold → minimum

"This is 'double what's working, reduce what's not' — implemented

STEP 16: Losing Streak Protection + Soft Circuit Breaker
----------------------------------------------------------
Phase: Backtest Decision Logic
Heading: "Two Safety Nets Against Catastrophic Loss"

Explanation:
Even a 52% win rate means we WILL have losing streaks. Two rules protect us:

Visual — two safety net cards:

  SAFETY NET 1: Losing Streak Protection
  ----------------------------------------
  Rule: After 2 consecutive losses → halve position size until next win
  
  Example:
    Trade 1: LOSS  (1 consecutive)
    Trade 2: LOSS  (2 consecutive) → now using 0.5x size
    Trade 3: LOSS  (3 consecutive) → still 0.5x
    Trade 4: WIN   → reset to 0, back to full size
  
  "Prevents a bad run from wiping out the account."

  SAFETY NET 2: Soft Circuit Breaker
  ------------------------------------
  Rule: If current equity is more than 10% below peak equity → halve size
  
  Example:
    Peak equity reached: $3,000
    10% below peak = $2,700
    If equity drops to $2,600 → use only 0.5x position size
    When equity recovers above $2,700 → return to full size
  
  "Unlike a hard stop (v5 mistake), this keeps trading alive
   but at reduced risk during drawdown periods."

Both can stack: During a losing streak AND drawdown → 0.25x size total.
