INTERFACE — SECTION 5: API DOCUMENTATION PAGE
================================================================

(For users who want to integrate signals into their own systems)

Heading: "REST API — Integrate Signals Into Your System"

API Endpoint cards:

  GET /api/v1/signal/current
  Returns the current 15-minute signal
  
  Response example:
  {
    "timestamp": "2025-02-01T14:30:00Z",
    "pair": "BTCUSDT",
    "direction": "LONG",
    "confidence": 0.80,
    "models_agree": 4,
    "models_total": 5,
    "velocity_multiplier": 1.4,
    "recommended_position": 1300,
    "tier": 3,
    "next_signal_at": "2025-02-01T14:45:00Z"
  }

  GET /api/v1/performance
  Returns current performance metrics
  
  GET /api/v1/signal/history?from=&to=&limit=
  Returns historical signals with results

Authentication:
  All requests require: Authorization: Bearer YOUR_API_KEY

Code example (Python):
  import requests
  r = requests.get(
      'https://signalbot-v9.com/api/v1/signal/current',
      headers={'Authorization': 'Bearer sk-xxxxx'}
  )
  signal = r.json()
  print(signal['direction'])  # 'LONG' or 'SHORT'
  print(signal['confidence']) # 0.80

Code example (JavaScript):
  const res = await fetch('https://signalbot-v9.com/api/v1/signal/current', {
    headers: { 'Authorization': 'Bearer sk-xxxxx' }
  });
  const signal = await res.json();
  console.log(signal.direction);  // 'LONG' or 'SHORT'

Webhook option:
  Users can register a webhook URL — the system will POST to their
  URL every time a new signal is generated (every 15 minutes).
  Webhook payload is identical to /signal/current response.

INTERFACE — HOW IT WOULD WORK IN PRODUCTION
================================================================

For the website's "How It Works" sub-section under Interface tab:

Step 1: CLOUD DEPLOYMENT
  The 5 trained models (.pt files) run on a cloud GPU server (e.g., GCP/AWS)
  A scheduler fires every 15 minutes at :00, :15, :30, :45
  It fetches the latest BTC/USDT OHLCV data from Binance API (last 97 candles)
  Runs through the full pipeline: features → scale → sequence → 5 models → vote

Step 2: SIGNAL GENERATION
  Checks consensus (≥80% agreement → trade, else skip)
  Applies velocity multiplier from rolling 50-trade window
  Determines tier-based position size
  Stores signal in database

Step 3: DELIVERY TO USER
  Option A (Auto-Execute): Places market order via user's Binance API
  Option B (Signal Only):  Pushes notification (email/Telegram/SMS)
  Option C (API):          User's system polls /signal/current endpoint
  Option D (Webhook):      System pushes to user's server automatically

Step 4: MONITORING
  All trades logged in real-time
  Dashboard updates every 15 minutes
  Performance metrics recalculated after each completed trade
  Anomaly detection: if drawdown exceeds 15%, pause auto-execution

Latency estimate:
  Data fetch:    ~200ms  (Binance API)
  Inference:     ~100ms  (5 models on GPU, chunked batching)
  Signal store:  ~50ms   (database write)
  Notification:  ~300ms  (email/Telegram delivery)
  TOTAL:         ~650ms  from candle close to signal delivery

  "The new candle opens at :15:00. The signal is delivered by :15:00.65.
  User has ~14 minutes 59 seconds to execute before the candle closes."
